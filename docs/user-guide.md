# 👥 Руководство пользователя

Короткая практическая документация по ролям и основным сценариям работы в CRM.

## Что умеет система

CRM покрывает пять сущностей:

- `Услуги` — то, что продает компания;
- `Рекламные кампании` — источники привлечения;
- `Лиды` — потенциальные клиенты;
- `Активные клиенты` — лиды после конверсии;
- `Контракты` — документы и суммы сделок.

## Роли и доступ

### `Superuser`

Полный доступ ко всему проекту.

Что делает:

- входит в Django admin;
- создает и редактирует пользователей;
- назначает группы и точечные permissions;
- видит и редактирует все CRM-сущности;
- может использовать приложение как любой бизнес-пользователь.

Когда нужен:

- первичная настройка проекта;
- управление учетными записями;
- разбор проблем с доступом;
- ручная проверка данных и ролей.

### `Operator`

Работает с лидами.

Что делает:

- создает лиды;
- редактирует лиды;
- удаляет лиды;
- просматривает список и карточки лидов;
- может открывать страницу статистики рекламных кампаний.

Что не делает:

- не управляет услугами;
- не управляет рекламными кампаниями;
- не конвертирует лиды в клиентов;
- не работает с контрактами.

### `Marketer`

Отвечает за маркетинговый контур.

Что делает:

- создает и редактирует услуги;
- создает и редактирует рекламные кампании;
- удаляет услуги и кампании;
- смотрит статистику кампаний.

Что не делает:

- не ведет лиды;
- не конвертирует клиентов;
- не работает с контрактами.

### `Manager`

Отвечает за продажи и сделку.

Что делает:

- просматривает лиды;
- запускает конверсию лида в активного клиента;
- создает первого клиента и первый контракт в одном действии;
- редактирует активных клиентов;
- создает, редактирует и удаляет контракты;
- смотрит статистику кампаний.

Что не делает:

- не создает и не редактирует услуги;
- не создает и не редактирует рекламные кампании;
- не ведет полный CRUD по лидам.

## Основные сценарии работы

### 1. Подготовка каталога

Обычно это делает `Marketer`.

Порядок:

1. создать услугу;
2. создать рекламную кампанию;
3. привязать кампанию к услуге;
4. указать бюджет и канал продвижения.

### 2. Регистрация лида

Обычно это делает `Operator`.

Порядок:

1. открыть раздел `Лиды`;
2. создать нового лида;
3. указать ФИО, телефон, email;
4. выбрать рекламную кампанию, из которой пришел лид.

Важно:

- телефон валидируется;
- email валидируется;
- контактные данные лида потом используются при создании клиента.

### 3. Конверсия в активного клиента

Обычно это делает `Manager`.

Порядок:

1. открыть карточку лида;
2. нажать `Конвертировать`;
3. заполнить данные первого контракта;
4. загрузить файл документа;
5. сохранить.

Что происходит внутри:

- создается `Customer`;
- создается первый `Contract`;
- в лиде фиксируется `converted_at`;
- повторная конверсия того же лида блокируется.

### 4. Работа с контрактами

Обычно это делает `Manager`.

Можно:

- создавать новые контракты из раздела `Контракты`;
- создавать контракт прямо из карточки клиента;
- заменять файл документа при редактировании;
- удалять контракт вместе с файлом документа.

Ограничения:

- разрешены файлы `pdf`, `doc`, `docx`, `txt`;
- размер файла ограничен 10 МБ;
- дата окончания не может быть раньше даты подписания.

### 5. Просмотр статистики кампаний

Доступно бизнес-ролям, у которых есть permission на статистику.

На странице статистики показывается:

- количество лидов по кампании;
- количество активных клиентов;
- выручка по контрактам;
- бюджет кампании;
- `efficiency ratio = revenue / budget`.

Если бюджет равен нулю, коэффициент не считается и отображается как `-`.

## Навигация по разделам

- `Главная` — краткая сводка по системе;
- `Услуги` — каталог услуг;
- `Рекламные кампании` — маркетинговые источники;
- `Лиды` — потенциальные клиенты;
- `Активные клиенты` — конвертированные лиды;
- `Контракты` — сделки и документы;
- `Статистика` — сводка по кампаниям;
- `Админка` — служебная зона администратора.

## Что важно администратору

Если доступы ведут себя не так, как ожидается, нужно проверить:

1. входит ли пользователь в нужную группу;
2. синхронизированы ли роли командой `python manage.py sync_roles`;
3. не назначены ли пользователю конфликтующие точечные permissions;
4. создан ли `superuser` для аварийного доступа.
